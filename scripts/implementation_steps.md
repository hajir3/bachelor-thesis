These are separate from the double-count fix in step 20; the bugs here concern missed source code rather than over-counted language entries. **Bug 1 (nested "dfsg-repacked" tarballs):** Debian in the 2003-2013 era commonly wrapped upstream source in a second tarball nested inside the `.orig.tar.*`; the outer tarball contained only a wrapper directory plus a single inner `.tar.{gz,xz,bz2}`. `scripts/03_analyze/analyze_tokei.sh` extracted the outer archive once and handed the wrapper directory to tokei, which scanned essentially nothing. Added a post-extraction loop (`find ... -maxdepth 3 \( -name '*.tar.gz' -o -name '*.tar.xz' -o -name '*.tar.bz2' \)` with a per-format `tar -x` and `rm -f` of the inner archive) so any nested tarball is extracted in place. Affected cells (that we confirmed): bash × {sarge, etch, lenny, squeeze, wheezy}, glibc × {potato, woody, sarge, etch, lenny}. **Bug 2 (`.orig.tar.xz.asc` overwriting the real tarball in parsed CSVs):** `scripts/02_parse/parse_sources.sh` matched `fname ~ /\.orig\.tar/`, which matches both `.orig.tar.xz` (real tarball) and `.orig.tar.xz.asc` (detached GPG signature). The change replaces `find … -exec pmccabe {} +` with `find … -print0 | xargs -0 -P "$(nproc)" -n 50 stdbuf -oL pmccabe`, fanning the per-file work across all cores Docker exposes. **Why this is safe for downstream awk.** `pmccabe` writes one line per function via `fprintf`. `stdbuf -oL` forces the libc stdout buffer to line mode, so each `fprintf` produces a single `write(2)`. The two awk passes downstream (`stats=$(awk … cc_out)` for sum/avg/max and the `complexity_functions.csv` row-emitter) are order-independent and see well-formed records identical in content to the serial output. **Per-package output ordering** in `complexity_detail.csv` is unchanged because the *outer* package loop is still sequential; only the inner per-file work is parallel. **Batch size `-n 50`.** Empirically a compromise between pmccabe startup overhead (one `exec` per batch) and pool-tail latency (a slow file in a 1000-file batch stalls one worker for the full batch). `-n 50` keeps each batch under a second of serial pmccabe time on typical input. **`nproc` fallback.** `nproc_val=$(nproc 2>/dev/null || echo 4)`; if `coreutils nproc` is unavailable the script still runs with a sane 4-way default.
